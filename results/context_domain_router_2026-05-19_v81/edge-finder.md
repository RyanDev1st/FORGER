# edge-context-domain-router

Edge lane for Context Domain Router.

## Input

Brief and `domain-ledger.md`.

## Mission

Find context-domain mistakes normal lanes miss: routine problems overcomplicated, complex problems flattened into best practices, chaotic conditions hidden behind confident synthesis, or disorder left unnamed.

## Selection rule

Prefer sources with:

- adjacent-domain failures caused by wrong response mode
- ignored dissent about context mismatch
- hidden stakeholder or incentive traps that change the domain
- dead prototypes revealing that simple-seeming problems were complex
- named or track-record pseudonymous practitioners

## Finding format

```markdown
### Finding E<n>: <edge domain finding>
- Domain id:
- Source:
- Verbatim quote: "<≤25 words>"
- Edge subproblem:
- Domain: clear | complicated | complex | chaotic | disorder
- Why normal lanes may misclassify it:
- Wrong-response risk:
- Hidden mechanism:
- Mitigation or kill criterion:
- Gate decision: pass | probe | analyze | stabilize | split | downgrade
```

## Drop rules

Drop mysticism, complexity theater, paranoia, unfalsifiable warnings, and novelty risks with no mechanism or kill criterion.

## Closing

List misclassification risks, weird domain shifts, disorder pockets, kill criteria, and visible residual risks.
