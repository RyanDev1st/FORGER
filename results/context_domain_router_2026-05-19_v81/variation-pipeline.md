# Variation Pipeline — Context Domain Router v81

## Status

v81. Search-first, browser-read, context-domain gated.

## Scope

This variation adds a context-classification pass before convergence so reTruth matches response mode to reality instead of forcing every topic into same research behavior.

## Pipeline

1. Search broad lead pool for decision-context frameworks, working examples, failures, repositories, datasets, and uncertainty guidance.
2. Open candidates directly with `playwright-cli`; record final URL, visible title, browser status, and quote.
3. Build `domain-ledger.md` with subproblem, domain, why this domain, wrong-response risk, required response, and route hint.
4. Decompose brief into claim clusters or subproblems before lane convergence.
5. Classify each cluster as clear, complicated, complex, chaotic, or disorder.
6. Match response to domain: clear gets best-practice checks, complicated gets expert analysis, complex gets probes/experiments, chaotic gets stabilizing action, disorder gets decomposition.
7. Route lanes with domain tags so search behavior changes with context.
8. Downgrade or block any synthesis that treats complex uncertainty like routine certainty.

## Audit checks

- Domain choice must have explicit evidence or artifact signal.
- Required response must match selected domain.
- Complex claims need probe path, not premature best practice.
- Chaotic claims need stabilization path before deep synthesis.
- Disorder must be decomposed before robust tier.
- Dead or mismatched pages cannot support domain claims.
