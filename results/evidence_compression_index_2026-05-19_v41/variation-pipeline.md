# Variation Pipeline — Evidence Compression Index

Parent: ARCHITECTURE.md

## Status
Created v41 variation centered on reducing apparent evidence breadth into independent trunks and mechanism clusters.

## Pipeline
1. Parse brief into central claim, expected evidence categories, suspected shared mechanisms, possible common datasets or provenance trunks, redundancy risk, independence threshold, and stakes.
2. Spawn three isolated lanes.
3. Force each lane to emit compression cards instead of generic findings.
4. Validate evidence trunk or mechanism cluster, independence or redundancy result, quote, recommendation, decision impact, and confidence.
5. Audit URLs, quote matches, trunk labeling consistency, and Edge redundancy.
6. Build compression map:
   - independent support
   - shared dataset trunk
   - shared mechanism cluster
   - citation echo
   - contextual duplicate
   - synthetic breadth illusion
   - true convergence
   - re-search gap
7. Synthesize after compressing redundant evidence into independent counts and mechanism clusters.
8. Re-fan one compression ambiguity if it changes recommendation strength.

## WHY
Evidence Compression Index improves reTruth by preventing many-source theater. Repeated findings often share same underlying trunk: same dataset, same model family, same benchmark, same incident, same origin paper, or same copied operational lore. This drift forces evidence accounting to distinguish true convergence from apparent multiplicity.

## Difference From Original
Original architecture removes direct redundancy but still allows apparent breadth from semi-dependent evidence. Evidence Compression Index explicitly models trunk structure and mechanism clustering before consensus strength is assigned.

## Expected Benefit
- Better independence accounting.
- Less false confidence from repeated evidence.
- Clearer identification of where new evidence must differ to matter.
- Stronger comparison between true convergence and shared-trunk repetition.

## Tradeoff
Can undercount partially independent support. Best for crowded evidence landscapes, benchmark-heavy domains, copied best-practice spaces, and repeated academic summaries; less useful when evidence sources are already clearly independent.

## Main Risk
Over-compressing genuinely diverse evidence. Mitigation: keep `true convergence` and `independent support` categories separate from `shared trunk` and `breadth illusion` categories.

## Next Variation Ideas
1. Decision Fork Map: produce branching recommendations under mutually exclusive assumptions.
2. Intervention Friction Audit: identify where implementation effort destroys theoretical benefit.
3. Temporal Drift Tracker: monitor how fast evidence relevance decays after publication or deployment.
