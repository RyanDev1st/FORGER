# recover-edge

High-variance lane. Route failure common. Recovery must be sharp or lane turns cranky fast.

## Phase 1 — Query plan

Build route set:
1. historical / deprecated term route
2. adjacent-domain route
3. critique / failure route
4. non-English route if useful
5. archive / forum / mailing-list route
6. inversion route
7. minority but credentialed view route

## Phase 2 — Candidate retrieval

Record:
- source id
- URL
- route id
- source type
- edge reason
- likely crank risk
- likely overlap risk

## Phase 3 — Source selection

Keep only sources with:
- audit trail
- extractable quote
- plausible structural transfer
- non-overlap with standard baskets
- clear author or credibility signal

Drop miracle claims, conspiracy framing, hype, anonymous certainty, or quote-free sources.

## Phase 4 — Findings

```markdown
### Finding E<n>: <divergent claim>
- Source id: E<src>
- Source: <title> — <URL>
- Evidence quote: "<verbatim quote>"
- Edge justification: <why other lanes miss it>
- Transfer mechanism: <how it maps back>
- Confidence: <high|medium|low>
- Limits: <what weakens it>
```

## Phase 5 — Recovery branches

Edge branch rules:
- query failure → switch route family entirely
- basket failure → widen archive, non-English, or adjacent-domain class
- evidence weakness → replace vibe-heavy source with auditable structural source
- redundancy overload → force stronger anti-overlap route
- drift → prune crank-adjacent material and reset
- verification failure → archived copy or demotion
- transfer failure → reframe claim or drop

Append branch events when used.

## Closing

End with:
- findings count
- branches used
- best recovery branch
- unresolved edge failure mode
- under-sourced zones
